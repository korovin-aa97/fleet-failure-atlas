# Fleet Failure Atlas v0.1.4

This release turns public feedback about a green no-op test job into a separate
clean-room executable pattern.

## FFA-006 — Green no-op test evidence

A required job can belong to the exact candidate revision, keep its expected
name, and report success while executing zero tests. The new fixture reproduces
that split with a synthetic structured test report:

```bash
python3 atlas.py run FFA-006 --mode reproduce
python3 atlas.py run FFA-006 --mode detect
python3 atlas.py run FFA-006 --mode regress
```

The detector checks positive expected work, executed and skipped counts, and
whether missing prerequisites were classified as unavailable evidence. The
regression rejects the no-op receipt while accepting both a complete required
suite and a named, policy-approved documentation-only non-applicability record.

The pattern is labelled `externally-reported` and links to the public discussion
that motivated it. Its fixture is independent, offline, bounded, vendor-neutral,
and contains no copied repository content.

The runner, pattern schema, and Python 3.11+ dependency-free runtime remain
unchanged.
